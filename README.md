# Stellar Burgers API Testing

Проект автоматизации API-тестирования для сервиса **Stellar Burgers**. Реализованы тесты для проверки эндпоинтов регистрации, авторизации пользователей и создания заказов с использованием REST Assured.

---

## 📋 Описание проекта

Проект содержит автоматизированные API-тесты для проверки следующих функциональных областей:

- **Создание пользователя**: проверка успешной регистрации, дублирование, отсутствие обязательных полей.
- **Авторизация пользователя**: проверка входа с корректными и некорректными данными.
- **Создание заказа**: проверка создания с авторизацией и без, с валидными и невалидными ингредиентами.
- **Получение ингредиентов**: проверка получения списка доступных ингредиентов.

Проект построен с использованием паттерна **Step Objects** для инкапсуляции API-вызовов и **Page Object** (в контексте API) для удобства поддержки тестов.

## 🔧 Настройка окружения

### Требования
- Установленная Java 11 или выше
- Установленный Maven 3.9.0+
- Доступ к API сервиса Stellar Burgers (по умолчанию `https://stellarburgers.education-services.ru/`)

### Конфигурация
Базовый URL API и тестовые константы хранятся в классах:
- `constants.Config` — содержит `BASE_URL`.
- `constants.TestConstants` — содержит тестовые данные (пароли, сообщения об ошибках, домены email и др.).

## 🚀 Запуск тестов

### Запуск всех тестов

```bash
mvn clean test
```

### Запуск конкретного тестового класса

```bash
mvn clean test -Dtest=UserCreationTests
mvn clean test -Dtest=UserLoginTests
mvn clean test -Dtest=OrderCreationTests
```

---

## 📊 Allure отчетность

### Генерация и просмотр отчета

```bash
mvn allure:serve
```
Эта команда сгенерирует отчет и откроет его в браузере.

### Сохранение отчета в файл

```bash
mvn allure:report
```
Отчет будет сохранен в папку target/site/.

## 🧪 Тестовые сценарии

### 1. Создание пользователя (UserCreationTests)

- ✅ Успешное создание нового пользователя.
- ✅ Создание пользователя, который уже существует.
- ✅ Создание пользователя без обязательных полей: email, password, name.
- ✅ Создание пользователя с пустым телом запроса.

### 2. Авторизация пользователя (UserLoginTests)

- ✅ Успешный вход существующего пользователя.
- ✅ Вход с неверным email.
- ✅ Вход с неверным паролем.
- ✅ Вход с неверным email и паролем.
- ✅ Вход без обязательных полей: email, password.
- ✅ Вход с пустым телом запроса.

### 3. Создание заказа (OrderCreationTests)

- ✅ Создание заказа авторизованным пользователем с валидными ингредиентами.
- ✅ Создание заказа неавторизованным пользователем с валидными ингредиентами.
- ✅ Создание заказа авторизованным пользователем без ингредиентов (ошибка).
- ✅ Создание заказа с невалидным хешем ингредиента (ошибка сервера).
- ✅ Создание заказа с частично невалидными ингредиентами (ошибка сервера).
- ✅ Создание заказа с несуществующим ID ингредиента (ошибка сервера).

## 📝 Примечания

- ✅ Для каждого тестового класса создается уникальный пользователь, который удаляется после выполнения тестов (в методе @After).
- ✅ Тесты используют динамически получаемые ID ингредиентов, что делает их устойчивыми к изменениям в базе данных.
- ✅ Все API-вызовы инкапсулированы в Step-классах для переиспользования и удобства поддержки.
- ✅ Используется библиотека Lombok для сокращения шаблонного кода в моделях.
- ✅ Для проверки ответов используются статус-коды HTTP и проверка JSON-полей с помощью REST Assured и Hamcrest.
